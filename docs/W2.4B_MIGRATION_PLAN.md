# W2.4b 迁移方案：tuition 零件 → `agent.skill` 插件（消 V2 双范式）

> 目标：把 `tuition/agents` 的四个「第二范式」零件归一到插件契约，消除方案里最后一个结构性违规
> **V2（`AgentCore` 自主环 vs `tuition` 确定性 FSM 并存、无统一契约）**。
> **§八 硬门禁**：**不删旧实现，直到等价用例证明**（本文件 §二 定义「何谓等价、每个零件保不保真」）。

---

## 一、现状（谁在用）

四个零件均被 `tuition.controller.ts`（+ `tuition.service.ts`）消费，**对外是既有端点**（前端在用）：

| 零件 | 是什么 | 状态 | 消费者 |
|---|---|---|---|
| `session-fsm` | **会话阶段** FSM（welcome→diagnosis→teaching→quizzing→done）+ **持久化 `edu.sessions`** | 有状态 | `tuition.service` · `tutor-session-agent` |
| `teaching-card-fsm` | **卡片态** FSM（Question/Hint/Scaffold/Solution/Reflection），**无状态**（transition 返回新态） | 纯 | `tuition.controller` |
| `intent-classifier` | **7 意图**（规则优先 + LLM 兜底） | 纯 | `tuition.controller` |
| `socratic-templates` | 模板 registry + 回退链 + 插值 + 缺件报错 | 纯 | `tuition.controller` |

## 二、等价基线（§八 门禁的**可执行定义**）

**基线已存在**，无需另写重复 spec —— 四个单元 spec 就是基线：

| 零件 | 基线（现有 spec） | 迁移后**必须**满足 | 保真？ |
|---|---|---|---|
| `session-fsm` | `agents/session-fsm.spec.ts`（迁移/所有权/flush 11 例） | 同对话 → 同 `{phase,state,message,questions?,diagnosisResult?}` **逐字等价** | ✅ **须逐字保真**（核心教学流） |
| `teaching-card-fsm` | `agents/teaching-card-fsm.spec.ts` | 同 `(state,intent,ctx)` → 同新态 / 同 `IllegalCardTransitionError` **逐字等价** | ✅ 须逐字保真 |
| `intent-classifier` | `agents/intent-classifier.spec.ts`（37 样本 ≥90%） | 同输入 → 同 `{intent,confidence}` 逐字等价 | ✅ 须逐字保真 |
| `socratic-templates` | `agents/socratic-templates.spec.ts` | 已定：**保留为能力 `socratic.render`，逐字保真**（§四.1-1）——不并入正文、不删 render 引擎 | ✅ 逐字保真 |

> **门禁落法**：迁移某零件后，其对应 spec **须在插件面绿**（不是在新写的件里另测）——即把 spec 的驱动目标从「直接 new 零件」换成「从宿主解析到该 capability 的 impl」，断言不变。**四个零件俱按「逐字保真」办**（含 socratic，见 §四.1-1）。

## 三、迁移形状（承契约 §二）

```
plugins/card-strategy/              # kind: agent.skill   ✅ 已落
  plugin.json  (kind agent.skill, provides ["card.strategy"])
  index.js     → { ... }            # 卡片态 FSM 单例（can/transition/advance + 三条 Guard + 转移表）
plugins/socratic/                   # kind: agent.skill   ✅ 已落
  plugin.json  (provides ["socratic.render"])
  index.js     → { ... }            # 模板 registry 单例（render = 解析 + 回退链 + 插值）
plugins/session-strategy/           # kind: agent.skill   ⬜ 待定（依存化归属 §四.2-1）
  plugin.json  (kind agent.skill, provides ["session.strategy"])
  index.js     → { tools, hooks: { onTurn } }   # 会话阶段 FSM（+ 若合入则卡片态一并）
plugins/intent/                     # kind: agent.skill   ⬜ 宿主须先暴露 LLM 能力（最深）
  plugin.json  (provides ["intent.classify"])  index.js → { tools:[intent.classify] }
```

- 宿主经 `@gri/plugin-host`（`loadPlugins` + `host.resolve('<capability>')`）装配；**不 pin 具体件**。
- `tuition.controller`/`service` 由「直接 `new SessionFsm`/`classifier`」改为「**DI 注入能力 token**（工厂从进程级宿主 `agentPlugins().host.resolve(...)` 解析）→ 调 impl」（**公共 controller 契约不变**）。
- 消费者侧判错：**按 `error.name`，勿用 `instanceof`**（插件错误类与宿主 import 的类身份不同，`instanceof` 恒假 → 400 会变 500）。
- **`PluginHost` 已支持 hook**（`manifest.hooks`+`impl[name]`，见 `plugin-host/src/host.js`）——`onTurn` 有机制落点（当前**零内置用例**，session-strategy 将是首个）。

## 四、开放决策（**需用户拍板**，勿擅断）

### 4.1 已定（2026-10-29，按「逐字保真优先」执行）

1. **`socratic-templates` 去留** → **保留为能力 `socratic.render`（逐字保真）**，不并入 SKILL.md 正文、不删 render 引擎。理由：契约 §二 的「并入正文」是**行为改变**（模板确定性 → LLM 生成），而 endpoint 在前端在用；`socratic-templates.spec` 的 10 条断言（插值/缺件报错/回退链/覆盖写）正是这条公共契约的可执行证明，删引擎即退场该证明。产物：`plugins/socratic`（provides `socratic.render`）。
2. **`teaching-card-fsm` 同样保真** → 插件 `plugins/card-strategy`（provides `card.strategy`），逻辑逐字迁入，`teaching-card-fsm.spec` 断言不变即等价门禁。**插件只出决策**，状态由请求方（前端）随每次 `POST agent/card/advance` 上送——它本就是无状态 FSM，与 §四-2 的持久化问题正交。

### 4.2 仍开放

1. **`session-fsm` 的持久化归属**：会话态写 `edu.sessions`（每轮 flush）。插件里**自管 flush**（要拿 `db`，插件不碰 apiKey 但可经 host 注入 store）？还是**持久化留在宿主、插件只出「决策」**（更符合「插件只描述能力」）？
2. **`tutor-session-agent`/旧编排**：契约标「废弃」，但你 2026-10-26 已裁「**直接删**，执行点 P-3.4」；本卡**是否即 P-3.4**（清零引用后删）？

### 4.3 迁移进度（按已定顺序）

| # | 零件 | 插件 / 能力 | 状态 |
|---|---|---|---|
| 1 | `teaching-card-fsm` | `plugins/card-strategy` → `card.strategy` | ✅ 已落 |
| 2 | `socratic-templates` | `plugins/socratic` → `socratic.render` | ✅ 已落 |
| 3 | `session-fsm` | 待定（§4.2-1 定了才好动） | ⬜ 未动 |
| — | `intent-classifier` | 宿主须先暴露 LLM 能力（最深） | ⬜ 未动 |

> 实际顺序调整为「**card-fsm → socratic → session-fsm**」：card-fsm 是最小最纯（无 LLM、无 SQL、无状态），
> 恰是**首件打样**的最佳选择——用它把「插件面等价范式」跑通，socratic 紧随验证「第二件不靠抄」。

## 五、风险（承 §八）

- **`session-fsm` 是最重的一步**：有状态 + 持久化 + 被 `tuition.service`/`tutor-session-agent` 依赖 → 放**最后**，且**先在插件面复现 `session-fsm.spec` 全绿**再切消费点。
- **无行为改变项**：§四.1 已定四零件俱逐字保真（socratic 亦保留 render 引擎）→ 无「删引擎」类改变，不必在提交里声明行为改变。
- **公共契约不变**：`tuition.controller` 端点形状**逐字节不变**（前端在用）——`tuition.controller.spec` 是这条的守卫。

> **本文件是「迁移的形状/基线/决策」记录，不含实现**。决策 §四 定了才好动手——尤其 1 与 2。
