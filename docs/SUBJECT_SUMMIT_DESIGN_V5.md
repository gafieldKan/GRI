## 0. 根因诊断：三条结构性问题（不是画得不够好）

| # | 问题 | 实测证据 |
|---|---|---|
| 1 | **山只表达"状态"，不表达"因果"** | 峰上有旗、有进度，但点亮一个点看不出"它为什么让下一个点可进"。海拔只回答"我在哪"，不回答"为什么这里打得开" |
| 2 | **山把两套体系压成一根竖轴** | 学科完整体系（分支峰）与 K12 体系（年级海拔）共用 `gradeY()` 同一根海拔轴 → 谁都不清楚 |
| 3 | **洞不是主要交互，被前置层稀释** | 实测入洞路径 = `pickHot → pickGradeDoor(年级洞门) → 节洞带 → openCave` = **4 层**；且洞被收成「1 洞=1 节」，**知识点只在洞里当灯位，不在世界上当洞口** |

**结论：打破"登顶"框架。** 微观裁决"1 洞 = 1 节，洞内展开到知识点"**升级为「知识点即洞口，铺在章内」**（见 §3）；变的只是外面那个世界长什么样。

## 1. v5 一句话

**不再是"去爬一座画好的山"，而是"逛一座会长大的城"——知识点的门就是一栋栋楼，路通不通一眼可见，打通一间，光顺路流向下一间。**

## 2. 三条机制如何从"山"搬到"城"

| v4 山的机制 | v5 城的对应 | 回应用户诉求 |
|---|---|---|
| M1 晨雾 = 未知 | 晨雾罩住未开门街区；雾退前沿 = 开拓边界 | ① 走过哪 / 还没往哪去，一眼可见 |
| M2 光脉 = 因果 | **道路 = 前置链**。路按课程序列铺；未掌握的点门前那段路是**施工围挡 + 雾**；打通 → 沥青铺点亮 → 光顺路流向下一栋 | ① "点亮 A → B 可进"变成**可走的路径**（本次最核心的一条） |
| M3 洞窟 = 闭环 | **楼门 = 知识点洞口** → 点门直达学科书房（主）+ 岩洞降为楼内可选地下室 | ②③ 洞从第 4 层变成**第 1 层** |
| 双维度一根竖轴 | **横 = 年级大道（K12）；纵 = 街区（学科完整体系）** | ④ 两套体系各占一个方向 |

## 3. 「知识点即洞」的粒度裁决

**用户原话是"山峰的每个知识点设置为山洞"**。库内实测决定它铺在哪一层：

| 实测 | 数字 | 含义 |
|---|---|---|
| 单章知识点数 | **8–35 个** | 「每个知识点一个洞」在**章内完全成立**——正好一栋楼能铺开的门面数 |
| 一门学科知识点数 | math **2354** | 在整个分支上铺满 = 噪声，**不铺** |
| 可练知识点（有题） | **math 2185 / phys 528 / chem 9 / chn 0 / eng 0** | **能真正铺满的城区只有 math 与 phys** |
| KP 有 `code` | 2873/2908；**chem/chn/eng 的 13 个全为 NULL** | `code` 是全链路键 → **chn/eng 的洞跑不了闭环** |

**裁决：楼门 = 知识点洞口，铺在`章内`（8–35 个真实可点）**；宏观仍按「街区（分支）→ 楼（章）→ 门（知识点）」进门。**用户原话被完整兑现，同时不炸。**

## 4. 诚实口径（红线：不编造）

库里**没有难度数据**（`level` 非空仅 **1/2908**）、**前置极少**（`prerequisites` 仅 **22/2908**，且 `explicit` 边实测全部落在同一节内）。故：

1. **城区没有难度轴。** 路的先后是**学习顺序**（先学后学），不是难度高低。图例逐字：*「路的先后是课程序列（先学后学的顺序），不是难度高低」*。
2. **`soft` 边只作引导**，虚线 + 最淡一档 + *「引导路径（非精确前置，仅供引导）」*，绝不画成必修。
3. **半亮 ≠ 掌握**：*「半亮 = 有作答且未到 80，不是 「会了一半」」*。
4. **chn / eng 不造假楼**：城区给明确空态（"该学科的节洞数据尚未收录"）+ 回维度 A 按钮。
5. **下楼 = 换屋子，不是换闭环**：*「地下室是同一间店的岩洞探索室，走的是同一条闭环；楼上楼下不改变掌握度真源」*。
6. **掌握度唯一真源**仍是 `edu.mastery_snapshots`（≥80）；`deriveLightState` 从不臆造掌握度（沿用 v4）。
