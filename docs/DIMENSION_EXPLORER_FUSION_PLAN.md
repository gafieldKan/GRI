## 4. 三视角方案

> 三方案**共用**：数据从 `ontology.region/industry` API 读、支持收藏/搜索/导出/笔记、接 S5 维护 + S6 AI。差异在**落地方式、抽象层级、复用范围**。

### 方案 A｜「移植」（Port & Skin）— **交付视角**
> 把两份 HTML 当作**独立 Explorer 前端**整体搬进 GRI，换 GRI 令牌皮肤，数据从内嵌 JSON 换成 `GET /api/dimensions/...`。

| 维度 | 设计 |
|---|---|
| 落位 | 新前端 `apps/dimension-explorer`（或 portal 内静态页），nginx 挂 `/explorer/` |
| 数据 | 内嵌 JSON → ontology API（region/industry 树 + 明细） |
| 样式 | 保留原 CSS，**覆写为 GRI 令牌**（teal≈twin 青） |
| 复用 | 低（两份独立代码） |
| 与 S5/S6 | 弱（另开维护入口） |
| **工作量 / 风险** | **S / 低** |
| **保真度** | **最高**（所见即所得） |
| 适合 | **想最快看到一模一样的效果** |

### 方案 B｜「融合」（Rebuild in GRI）— **产品视角** ★推荐骨架
> 用 GRI 技术栈（uni-app + 设计令牌 + ontology API）**重写为「维度浏览器 / 治理台」**，拆成可复用组件，融入 portal，**挂到插件注册表**，**接 S5 维护 + S6 AI 命令**。

| 维度 | 设计 |
|---|---|
| 落位 | **portal 内的插件**（`/portal/` 的"维度浏览"页）或独立 app + 门户入口 |
| 组件 | `TaxonomyTree` / `VisualStage(treemap｜geo｜graph｜list)` / `DetailPanel` / `ExportMenu` / `GlobalSearch` |
| 数据 | ontology API（新增 `/api/dimensions/{region,industry}` 树/明细/搜索端点） |
| 样式 | 全走 `styles/tokens/` 令牌（单一真源） |
| 复用 | 中（组件可被其它页复用） |
| 与 S5/S6 | **强**（维护入口 + AI 命令直接嵌在 Explorer 内） |
| **工作量 / 风险** | **L / 中**（可视化最费工） |
| **保真度** | 高（重构但视觉对齐） |
| 适合 | **要长期的产品级功能** |

### 方案 C｜「引擎化」（Ontology-driven Explorer Engine）— **架构视角**
> 抽象为**本体驱动的通用分类法浏览器引擎**：任意本体树（region / industry / subject / knowledge_area / twin…）皆可渲染；视图**可插拔**；两份文件降级为**两个实例配置**。

| 维度 | 设计 |
|---|---|
| 核心 | `ExplorerEngine(ontologyTree, {views:[...]})`；视图注册表（tree/treemap/geo/graph/list 各自是插件）；统一搜索/明细/导出/收藏/笔记 |
| 实例 | `region`（geo 视图）、`industry`（treemap 视图）、未来 `subject`…（配置驱动） |
| 数据 | 泛化端点 `/api/ontology/taxonomy/:name/...` |
| 样式 | 令牌 + 引擎默认皮肤 |
| 复用 | **最高**（一次投入，全 taxonomy 受益） |
| 与 S5/S6 | 强（治理/AI 命令作用于任意 taxonomy） |
| **工作量 / 风险** | **XL / 中高**（先定引擎契约，前期见效慢，易过度设计） |
| **保真度** | 中（需为每个视图复刻） |
| 适合 | **把它变成平台的"基础设施"** |

## 6. 推荐与决策点

**推荐：`B 为骨、C 为魂、A 为速`。**
- **落地**：用 **B（融合）** 做首个实例（区域 + 行业），但**组件按 C（引擎）的契约来设计**（视图可插拔、本体驱动、配置化），避免日后二遍返工。
- **过渡**：若你想**先看效果**，可先用 **A（静态托管）** 把两份文件挂 `/explorer/` 作**临时预览**（换肤可后补），不当正式架构。
- **与既有计划的关系**：把 **S5（维护）/ S6（AI 命令）融入 Explorer**（Explorer 即维度的浏览 + 治理界面）；S2~S4 的"维度=插件作用域"保留为**附加能力**。

**需你拍板（决定走哪条/怎么走）：**
1. **落位**：Explorer 作为 **portal 内插件**，还是**独立 app**（门户入口）？
2. **视图优先级**：先做 **treemap（行业）** 还是 **geo（区域）**？（geo 需真实边界几何——我们此前**丢弃了地图几何**，若要真地图需从源文件重新抽取 `maps`/`countryShapes`）
3. **视图范围**：3 视图（地图/层级图/列表）全上，还是先上 1~2 个？
4. **皮肤**：保留「域览」teal 原味，还是**并入 GRI 令牌**（food 绿 / twin 青）？
5. **导出**：Excel/PNG/JSON 是否都要（PNG 需 canvas 截图；Excel 需 xlsx 库）？
6. **与 S5/S6 的关系**：维护入口/AI 命令是否**内嵌 Explorer**？
7. **移动端**：是否要手机端可用（uni-app 可多端）？
