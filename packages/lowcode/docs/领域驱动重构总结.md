# 领域驱动重构总结文档

## 一、重构概述

本次重构基于**领域驱动设计 (DDD)** 理念，按照**功能模块**维度，采用**抽象类**和**接口**设计，实现**松耦合、紧聚合**的架构目标。

---

## 二、架构分层

```
┌─────────────────────────────────────────────────────────────┐
│                    UI Layer (React)                          │
│   RestaurantList / MenuPage / CartPage / OrderPage ...     │
├─────────────────────────────────────────────────────────────┤
│              State Management Layer                          │
│   CartState / OrderState / UserState (基于 BaseState)       │
├─────────────────────────────────────────────────────────────┤
│              Service Layer (业务逻辑层)                      │
│   RestaurantService / DishService / OrderService / Cart... │
├─────────────────────────────────────────────────────────────┤
│              Domain Layer (领域模型层)                       │
│   Restaurant / Dish / Order / Cart / User (实体 + 值对象)   │
├─────────────────────────────────────────────────────────────┤
│           Repository Layer (数据访问层)                      │
│   RestaurantRepository / DishRepository / OrderRepository...│
├─────────────────────────────────────────────────────────────┤
│              API Client Layer (网络层)                       │
│   ApiClient (拦截器、缓存、重试)                            │
├─────────────────────────────────────────────────────────────┤
│              Data Source Layer (数据源)                      │
│   REST API / LocalStorage / InMemory ...                    │
└─────────────────────────────────────────────────────────────┘
```

## 三、核心设计原则

### 3.1 面向对象设计
- **封装**: 所有实体使用私有字段 (`#field`)
- **继承**: 领域模型继承 `BaseDomain`，Repository 继承 `BaseRepository`
- **多态**: 服务接口与实现分离

### 3.2 设计模式应用
| 模式 | 应用场景 |
|------|---------|
| 工厂模式 | Repository 创建 |
| 策略模式 | DataSource 策略 |
| 单例模式 | ApiClient, StateManager |
| 观察者模式 | State 订阅机制 |
| 装饰器模式 | TransactionalService |
| 模板方法模式 | BaseService |

### 3.3 松耦合设计
- UI 层不直接调用 Repository
- Service 层通过接口依赖
- 领域事件解耦领域模型

## 六、服务层 API 设计

### 6.1 餐厅服务接口
```javascript
interface IRestaurantService {
  getRestaurant(id: string): Promise<Restaurant>
  getRestaurantList(condition: Object): Promise<Restaurant[]>
```

## 七、使用示例

### 7.1 创建餐厅
```javascript
import { RestaurantService } from './service/RestaurantService.js'
import { RestaurantRepository } from './repository/RestaurantRepository.js'
import { RestApiDataSource } from './repository/BaseRepository.js'

// 创建数据源
const dataSource = new RestApiDataSource('https://api.example.com')

// 创建 Repository
const repository = new RestaurantRepository(dataSource)

// 创建 Service
const restaurantService = new RestaurantService(repository, eventPublisher)

// 业务调用
const restaurant = await restaurantService.createRestaurant({
  name: '麦当劳',
  code: 'mcd_001',
  cuisine: ['快餐', '汉堡'],
  deliveryRange: 5,
  deliveryFee: 9
})
```

### 7.2 状态管理
```javascript
import { CartState } from './state/BaseState.js'

// 创建状态
const cartState = new CartState()

// 添加商品
cartState.addItem({
  dishId: 'dish_001',
  dishName: '巨无霸',
  price: 32,
  quantity: 1,
  restaurantId: 'rest_001'
})

// 订阅状态变化
cartState.subscribe((state) => {
  console.log('购物车状态变化:', state)
})
```

## 十、总结

### 10.1 架构优势
1. **清晰的层次划分**: 各层职责明确
2. **松耦合设计**: 层与层之间通过接口通信
3. **可测试性强**: 每个服务可独立测试
4. **可扩展性好**: 新增功能不影响现有代码

### 10.2 设计模式应用
- 工厂模式、策略模式、单例模式等 GoF 模式
- Repository 模式解耦数据源
- 观察者模式实现状态管理

### 10.3 符合 SAP 规范
- 配置化设计
- 全球化支持
- 模块化架构
